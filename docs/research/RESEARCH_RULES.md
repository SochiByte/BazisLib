# Назначение документа

Этот документ определяет правила проведения исследований
в рамках проекта SochiCabinetMaker.

Цель правил:

- сохранить достоверность информации;
- обеспечить повторяемость экспериментов;
- исключить потерю исследовательских данных;
- обеспечить единый формат документации.


------------------------------------------------------------

# Основной принцип исследования

Исследование начинается не с написания кода.

Последовательность работы:

Гипотеза
    ↓
План проверки
    ↓
Эксперимент
    ↓
Результат
    ↓
Документирование
    ↓
Вывод


------------------------------------------------------------

# Правило достоверности

Запрещено считать фактами неподтвержденные данные.

Любая информация должна иметь источник:

1. Официальная документация.

2. Результат эксперимента.

3. Анализ программных файлов.

4. Анализ поведения программы.

5. Повторная проверка.


Если информация не подтверждена:

Статус:
    Гипотеза


Если информация подтверждена:

Статус:
    Подтверждено


------------------------------------------------------------

# Структура исследования

Каждое исследование должно содержать:

1. Название.

2. Цель.

3. Предположение.

4. Метод проверки.

5. Используемые инструменты.

6. Результат.

7. Вывод.


------------------------------------------------------------

# Правила создания Probe

Probe — это исследовательская программа.

Каждый Probe:

- решает только одну задачу;
- имеет понятное название;
- сохраняет результат;
- имеет описание.


Формат имени:

номер_назначение_тип.js


Примеры:

0001_runtime_environment_probe.js

0002_object_collection_probe.js

0003_api_method_probe.js


------------------------------------------------------------

# Правила результатов

Все результаты экспериментов сохраняются.


Место хранения:

C:\Users\SochiByte\Documents\Bazis\SochiCabinetMaker\output


Имя результата должно соответствовать Probe.


Пример:

Probe:

0001_runtime_environment_probe.js


Результат:

0001_runtime_environment_probe.txt


------------------------------------------------------------

# Правило вывода результатов исследований

Все информационные Probe обязаны сохранять результат
в файл.


Поле Log редактора БАЗИС используется только для:

- быстрых проверок;
- коротких сообщений;
- подтверждения запуска.


Для больших дампов используется только файл.


Причина:

Редактор скриптов БАЗИС позволяет копировать строки
из Log, но это неудобно и непригодно для больших
исследований API и Runtime.


Стандартное место хранения результатов:

C:\Users\SochiByte\Documents\Bazis\SochiCabinetMaker\output


Формат имени результата:

<номер>_<имя_probe>_result.txt


Пример:

Probe:

0001_runtime_environment_probe.js


Результат:

0001_runtime_environment_probe_result.txt

------------------------------------------------------------

# Запрещается

Запрещается:

1. Выдумывать существование методов.

2. Делать вывод по одному неудачному эксперименту.

3. Удалять результаты исследований.

4. Изменять старые результаты.

5. Смешивать разные эксперименты в одном Probe.


------------------------------------------------------------

# Работа с ошибками

Ошибка является результатом исследования.

Каждая ошибка должна быть записана.

Неудачный эксперимент не является бесполезным.

Он показывает ограничение системы.


------------------------------------------------------------

# Работа с версиями

Все исследования относятся только к:

БАЗИС-Мебельщик 2026 Online


При обнаружении различий между версиями:

старые версии не используются как источник истины.
