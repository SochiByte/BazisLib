# 2. Глобальная область состояния

Обнаружена глобальная область:

```
DAT_02b6f7d0
```

Тип, определённый Ghidra:

```
undefined8
```

По характеру использования переменная рассматривается
как указатель на внутренний объект ScriptEditor.

Это является результатом анализа обращений к данной
области из нескольких функций.

---

# 4. PrepareSE

Экспорт:

```
PrepareSE
```

## Установленный результат

Функция участвует в создании/подготовке объекта
ScriptEditor.

После выполнения операции в:

```
DAT_02b6f7d0
```

сохраняется указатель на созданный объект.

Обнаружен фрагмент:

```text
MOV qword ptr [DAT_02b6f7d0], RAX
```

---

## Дополнительное наблюдение

В зависимости от режима также обнаружено использование:

```
DAT_02b6f7d8
```

как указателя на объект PM-системы.

Точная структура обоих объектов пока не установлена.

---

# 5. RunSE

Экспорт:

```
RunSE
```

## Установленный результат

Функция связана с запуском Script Engine.

В процессе работы используется:

```
FUN_027fce00
```

которая получает внутренний объект ScriptEditor.

Также присутствует вызов:

```
SEOpenFile
```

---

## Предварительный вывод

Цепочка:

```
RunSE
   |
   +--> FUN_027fce00
   |
   +--> SEOpenFile
```

связана с выполнением/запуском скриптового механизма.

---

# 6. SetOnRunScriptCallback

Экспорт:

```
SetOnRunScriptCallback
```

## Установленный результат

Функция получает два указателя через:

```
RCX
```

Полученные значения записываются во внутренний
объект, связанный с:

```
DAT_02b6f7d0
```

Обнаружено использование смещения:

```
+0xe78
```

---

## Вывод

Функция устанавливает callback, связанный
с выполнением скрипта.

Точная сигнатура callback пока не установлена.

---

# 7. SetOnRunDebugScriptCallback

Экспорт:

```
SetOnRunDebugScriptCallback
```

## Установленный результат

Функция устанавливает callback во внутреннем объекте.

Обнаружено смещение:

```
+0xe88
```

---

## Вывод

Объект ScriptEditor содержит отдельное поле,
связанное с callback выполнения отладочного скрипта.

Точная сигнатура callback пока не установлена.

# 12. Что пока НЕ установлено

Не установлены:

* точная структура объекта ScriptEditor;
* точный C/C++-тип DAT_02b6f7d0;
* точные сигнатуры экспортов;
* точные типы параметров;
* точные возвращаемые значения;
* полное назначение callback-полей;
* точные сигнатуры callback-функций;
* назначение всех полей объекта;
* полный call graph ScriptEditor;
* механизм связи ScriptEditor.dll с Bazis.exe;
* внешний протокол взаимодействия;
* возможность безопасного вызова DLL из отдельного процесса.

# 14. Статус гипотезы

Статус:

```
HYPOTHESIS
```

Гипотеза состоит в том, что `ScriptEditor.dll` может
предоставлять механизм внешнего управления Script Engine
посредством экспортируемых функций и callback-механизмов.

Это пока НЕ подтверждает возможность:

```
отдельная программа
      |
      v
ScriptEditor.dll
      |
      v
уже запущенный БАЗИС
```

Такой сценарий ещё необходимо экспериментально проверить.


6. Исследовать:

   ```
   FUN_027fce00
   ```

   ```
   FUN_027f1180
   ```

9. Найти места вызова callback.

    внешнего вызова DLL.

```

HYPOTHESIS
```

не присваивать ему окончательное назначение
только на основании имени.
